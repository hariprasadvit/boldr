# 04 · Roadmap & Progress

A multi-week build. The goal is to consolidate the three current implementations onto one
production backend (`backend/`) + a React frontend, and to actually close the brief's gaps
(real human-in-the-loop, self-improving KB, scheduled intelligence).

## Locked decisions (see [07-decisions.md](07-decisions.md) for rationale)
- **Stack:** FastAPI + React (Vite), single-process. **Not** Next.js.
- **LLM:** provider-agnostic via **LangChain → OpenRouter**. No vendor SDK.
- **Database:** **Neon** (managed serverless Postgres + pgvector) — one database, no Docker.
- **Embeddings:** dedicated **API** (Jina/Voyage/Cohere) behind an `EmbeddingClient` interface (default 1024-d).
- **HITL:** build the **real** human approval queue now (LangGraph `interrupt()` + Postgres checkpointer), not a status flag.
- **Deploy:** **Vercel only**, no Docker — React static + FastAPI serverless function; offline jobs write to Postgres.
- **Order:** **backend first** (all endpoints working, testable via `/docs`), then the React frontend.
- **Tooling:** **uv** (backend), **pnpm** (frontend).

## Immediate next step (when unblocked)
1. **Provision a Neon project** with the pgvector extension; copy its **pooled** + direct URLs.
2. **Get an embeddings API key** (Jina / Voyage / Cohere) and confirm the dim (default 1024).
3. `cd backend && cp .env.example .env`; paste `OPENROUTER_API_KEY`, `EMBEDDING_API_KEY`, and the Neon `DATABASE_URL`.
4. Then I run **Phase 2**: `alembic revision --autogenerate` against Neon → `make migrate`. (ORM models are already written; the migration is autogenerated, not hand-written.)
