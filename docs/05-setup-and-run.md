# 05 · Setup & Run

Covers the **new backend** (go-forward) and the **two legacy apps** (still runnable today).
Prerequisites: macOS, [`uv`](https://docs.astral.sh/uv/), Node 20+, and (for the backend DB)
**Docker Desktop** (to be installed).

## Secrets / environment
Every app routes LLM calls through **OpenRouter** via the OpenAI-compatible endpoint.
You provide one key. **`.env` files are gitignored and currently hold placeholders — paste your real key; never commit it.**

| Variable | Used by | Default / note |
|----------|---------|----------------|
| `OPENROUTER_API_KEY` | all | **required** — your OpenRouter key (`sk-or-...`) |
| `OPENROUTER_MODEL` | all | `anthropic/claude-sonnet-4.6` (any OpenRouter slug) |
| `OPENROUTER_BASE_URL` | all | `https://openrouter.ai/api/v1` |
| `DATABASE_URL` | backend | **Neon** pgvector URL (use the **pooled** host on Vercel). No Docker. |
| `EMBEDDING_PROVIDER` / `EMBEDDING_MODEL` / `EMBEDDING_DIM` | backend KB | `jina` / `jina-embeddings-v3` / `1024` |
| `EMBEDDING_API_KEY` | backend KB | key for the chosen embeddings provider (Jina/Voyage/Cohere) |
| `CORS_ORIGINS` | backend | `["http://localhost:5173"]` |
| `STATIC_DIR` | backend (prod) | path to built React app |

> Tooling: **uv** for the backend, **pnpm** for the frontend.

## A) New backend (FastAPI) — go-forward
```bash
cd backend
cp .env.example .env          # paste OPENROUTER_API_KEY + EMBEDDING_API_KEY + Neon DATABASE_URL
uv sync                        # install deps (request-path only; add --group offline for jobs)

# --- DB: create a Neon project with pgvector, put its POOLED URL in .env (no Docker) ---
make migrate                   # apply schema (Alembic autogenerated)   (Phase 2)
make seed                      # personas + KB + tickets                (Phase 5)

make dev                       # → http://localhost:8000/docs
```
Offline intelligence jobs need the extra group: `uv sync --group offline` then
`uv run python -m app.scripts.cluster_themes` (etc.) — these write results to Postgres.

**Boots without a DB:** `uv run uvicorn app.main:app --reload --port 8000`, then
`GET http://localhost:8000/api/v1/health` → `200 {"status":"ok"}`. (`/health/db` needs Neon.)

Makefile targets: `install, db-up, db-down, dev, migrate, revision m="msg", seed, seed-kb, run-baseline, test, lint, fmt`.

## B) Legacy Python engine + Streamlit  *(implementation #1)*
```bash
cd boldr                                   # repo root
cp .env.example .env                       # paste OPENROUTER_API_KEY
uv sync
uv run python -m kb.ingest                 # build ChromaDB KB (~30s, no key needed)
uv run python batch_replay.py              # run all tickets → outputs/ (needs key; ~8 min)
uv run python -m intelligence.cluster_themes
uv run python -m intelligence.marketing_brief
uv run python -m intelligence.external_bench
uv run streamlit run demo_app.py           # → http://localhost:8501
```
Smoke test cheaply: `uv run python batch_replay.py 3`.

## C) Legacy Next.js web app  *(implementation #2 — the Vercel demo)*
```bash
cd web
cp .env.example .env.local                 # paste OPENROUTER_API_KEY
npm install
npm run dev                                # → http://localhost:3000
```
Dashboards render from committed `web/public/data/*.json`; only the live tab needs the key.

## Which one should I run?
- **Want the go-forward app / to develop further** → **A (backend)**.
- **Want to see the upgraded Python engine working end-to-end** → **B (Streamlit)**.
- **Want the polished demo UI** → **C (Next.js)**.

## Stopping servers
```bash
lsof -ti:8000 | xargs kill   # backend
lsof -ti:8501 | xargs kill   # streamlit
lsof -ti:3000 | xargs kill   # next.js
```

## Troubleshooting
- **`401 Missing Authentication header`** → `OPENROUTER_API_KEY` is still the placeholder.
- **Python 3.14 wheel errors** → use 3.13 (pinned via `.python-version`; `uv` handles it).
- **`/health/db` fails** → Postgres isn't up (`make db-up`, needs Docker).
